# ALPHA FORGE 開発秘話 ネタストック（連載管理）

note.com 連載「ALPHA FORGE 開発秘話」の**ネタ在庫と進行管理**。1回＝スマホで5分前後（本文2,500〜3,500字）で
読める分量に切り出し、1日1話ずつ小出しに公開する。デイリーAIピック記事（`YYYY-MM-DD/note.txt`）とは
ファイル名を分け、各話の本文は `docs/note/YYYY-MM-DD/dev_note_epNN.txt` に置く。

ネタの出典は Claude Code との過去の会話履歴（2026-09-10〜）、`plans/05_決定ログと未決事項.md`、
`git log` のコミット本文、`docs/operations.md`。数字・日付は出典で確認済みのものだけを使う。

## 連載を貫く軸：Human in the Loop（2026-09-23 ユーザー方針、第2話以降に適用）

- ALPHA FORGE は「AIが全部作った／全自動で動く」話ではない。**AI（Claude Code）は良い相棒**であり、
  方向を決める・確かめる・止める・最終判断するのは人間、という Human in the Loop の開発記録として書く。
- プロダクト自体も同じ思想: AIは提案まで（モデル昇格は承認制、ポートフォリオ判断は承認チケット、発注機能なし）。
  「作り方」と「プロダクト」の両方が Human in the Loop である、という二重構造を連載の核にする。
- 各話で「誰が気づき／誰が作り／誰が決めたか」を明示する（下の各話ネタの「🤝 役割分担」行を使う）。
  AIの強み（速さ・網羅的な調査・実測による原因特定・規約確認）は素直に書き、人間の役割（違和感に気づく・
  実画面や実データで確かめる・方針と予算を決める・公開/コミット/課金を承認する）と対で見せる。
- 表現ガイド: 「全自動」「放置で完成」「AIが全部やった」「人間は何もしていない」は使わない。
  「相棒」「二人三脚」「AIが提案し、人間が決める」「人間が気づき、AIが突き止める」を使う。
- 第1話（公開済み）は「入力は『次』『続行』の2語」と AI 主導に読める書き方をしている。第2話または第3話の冒頭で
  「あの2語が成り立ったのは、前日に人間が『約束』を書き切っていたから。そして2話目以降は人間の出番だらけ」と
  やわらかく補足し、軸を立て直す（第1話は修正しない）。

## 連載の3本柱（2026-09-23 ユーザー要望で追加）

1. **事件簿**: 実際に起きた障害・失敗と、その原因と対処（連載の主軸）
2. **プロンプトエンジニアリング**: AI（Claude Code）への指示の書き方と、アプリ内LLMへのプロンプト設計
3. **ハーネスエンジニアリング**: Claude Code を「使いこなす仕組み」側の設計（CLAUDE.md・スキル・メモリ・フック・/loop・
   サブエージェント・計画モード・ローカルCI）

柱2・3は専門回（下表の【P】【H】）で深掘りしつつ、事件簿回でも末尾に「🧰 今回のプロンプト／ハーネス術」を
1コーナー（300〜500字）置き、その事件から生まれた指示文・ルール・スキルを紹介する。事件→仕組み化の流れを毎回見せる。

## 執筆ルール（この連載固有）

- 書式・文体・コンプライアンスは `NOTE.md`（系統B）と `docs/note/templates/dev_note_template.txt` に従う。
  ただし連載1話ぶんに収めるため、テンプレの7章をそのまま使わず「導入＋3〜4大見出し＋次回予告＋CTA＋免責」に圧縮する。
- 大見出しは絵文字始まり（note.com エディタの `N. ` 自動番号リスト化を避ける。`note-com-draft` スキル参照）。
- **公開NG**: ローカルパス、ユーザー名、APIキー名の実値、メールアドレス、前身ツールの固有名（「前身の自作ツール」と書く）、
  推奨買値/損切値/売値の具体値、個別銘柄の売買推奨と取れる表現。
- プロンプト・CLAUDE.md・スキルを引用するときは要旨か短い抜粋にとどめ、パス・キー・環境固有値はダミーに置き換える。
- Human in the Loop を貫く（上記「連載を貫く軸」）。AIの手柄も人間の手柄も盛らない。
- 失敗は失敗として書く。盛らない（実測値が無いものは数字を出さない）。
- 各話の末尾で次回予告を1行入れる。公開後は下の進行表の「状態」「公開日」を更新する。
- ハッシュタグ（毎話共通の核）: `#ALPHAFORGE開発秘話 #個人開発 #ClaudeCode #AIエージェント #生成AI #機械学習 #日本株`
  ＋回ごとに2〜3個（【P】回は `#プロンプトエンジニアリング`、【H】回は `#ハーネスエンジニアリング` `#CLAUDEmd` 等）。
  `#株式投資` `#投資` など売買を連想させるタグは付けない。

### #02 初めての朝、AIピックが1銘柄のせいで全滅した【事】

- 2026-09-13 夜〜09-14: 「ピック生成に失敗しました」「設定画面がでないのもそのせい？」。
- J-Quants の無料プランでは必要データが取れず、その場でプランを更新。
- 根本原因（コミット `fix: ピック生成のブロッキングI/Oと1銘柄失敗時の全滅を修正`）:
  yfinance の同期呼び出しを async 関数内で直接実行 → 候補銘柄ごとにイベントループ全体が停止し
  バックエンド全体が応答不能。さらに1銘柄の取得失敗（サーキットブレーカOPEN等）が500として全体を落としていた。
  → `asyncio.to_thread` で逃がす＋銘柄単位で try/except スキップ。
- 同日、ナレッジベース検索API（別サービス）が未起動 → 全銘柄で30秒タイムアウトを繰り返しピック生成が大幅遅延。
- 🧰 コーナー: 「AIピックに失敗しています。根本原因をさぐってください」― 症状でなく**根本原因**を求める一言の効き目。
  そして「システム起動して」と言われたら依存サービスまで全部確認する、というルールが CLAUDE.md に入った（→ #05）。
- 🤝 役割分担: 「失敗しています、根本原因をさぐって」と異変を拾い、J-Quants の有料プラン更新（契約・課金）を決めたのは人間。AIは原因特定と修正。AIの“完成”は人間が朝に実際に動かすまで完成ではなかった。
- 出典: 会話ログ 09-13〜14、コミット本文、`docs/operations.md` §4.5。

- 題材: `新規プロジェクト構築プロンプト.md` の章立て（公開時は要旨のみ・パス等はダミー）。

### #05 CLAUDE.md はプロジェクトの憲法 ― 事件が起きるたびに条文が増えた【H】

- CLAUDE.md = Claude Code が毎セッション最初に読む「プロジェクト固有ルール」。一般論は書かず、このプロジェクトでしか
  通用しない約束だけを書く方針（冒頭に明記）。
- 条文の例（公開時は要旨）:
  - ドメイン: 時刻はJST・大引け15:00、上げ赤/下げ緑をトークン経由で、銘柄コードは4桁で `.T` を付けない。
  - 安全: 外部テキストをプロンプトへ入れない境界、ブローカー発注を一切しない、モデル昇格は提案のみ。
  - Git: 同じ作業ツリーを人間も並行編集するので **`git add -A` 禁止**（対象ファイルを明示 add）、フェーズごとにコミット。
  - 検証: push 前にローカルCI相当（ruff/black/mypy/bandit/pytest、tsc/jest/eslint/next build）を全通し。
- **口癖をマクロにする**: 「システム起動して」＝ frontend/backend/Redis/worker/beat/ベクトル検索API を確認し、止まっているものだけ起動。
  「Note作成」＝ 下書き生成→書き出し→note.com へ下書き保存まで（公開は押さない）。
- **事件→条文**の年表: 09-14 ナレッジ検索API未起動で遅延 → 起動チェックリスト追加 / 09-14 beat 一斉発火 → beat を自動起動対象外に
  → 09-22 根本原因解消を確認して起動対象へ戻す（条文は削除・改正もする）/ 09-17「公開まで一気に」→「下書きまで」に確定 /
  09-18 インジェクション抜け穴 → 境界条文にトレンド分析経路を追記。
- グローバル設定（全プロジェクト共通の CLAUDE.md とルール群）との二層構造: 日本語で会話・コミット、可逆な作業は確認なしで自走、
  コミット/push/公開/削除は確認必須。
- 🤝 役割分担: 条文はインシデントを見た人間が「今後はこうして」と決めたもの。AIは条文案を書き、人間が採否・改正・削除を判断する。
- 出典: `CLAUDE.md`、`git log -- CLAUDE.md`、`plans/05` 2026-09-22。

### #08 LLMに「3つの価格」を言わせる ― 強制ツール呼び出しとサーバ側検証【P】

- 題材: `backend/services/picks/prompt.py`（`build_pick_prompt`）。
- 設計:
  - LLMに自由に語らせず、**強制ツール呼び出し（forced tool-use）`propose_stock_pick`** で
    推奨買値・損切値・売値・確信度・根拠を**型の決まった形**で返させる。
  - 材料は「自分の定量分析結果」: 合成スコア、方向一致度、サブスコア内訳、テクニカル/ファンダシグナル、
    ATRベースの目安ブラケット。LLMはゼロから考えるのではなく**定量分析の上に解釈を足す**役割。
  - 外部由来の情報は frontmatter・enum・数値だけを「外部由来」と明記して載せる（→ #09）。
