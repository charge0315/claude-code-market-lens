# アーキテクチャ — Alpha Forge

> 出典: `新規プロジェクト構築プロンプト.md` §5 / 再利用元: Market Lens
> 方針: Market Lens のレイヤ構成を踏襲しつつ、6 つの新規領域（N1〜N6, [`00_調査サマリ`](00_調査サマリ_MarketLens移植棚卸し.md)）を追加する。

---

## 1. 技術スタック

| レイヤー | 技術 | ポート / 備考 |
|:--|:--|:--|
| frontend | Next.js 16 + TypeScript (strict) / Vanilla CSS（Tailwind 禁止） | **3001**。デザイントークン単一情報源 `frontend/src/app/tokens.css` |
| backend | FastAPI + Python 3.11（型必須 / Pydantic v2 `frozen=True` / `Any` 禁止） | **8002** |
| DB | SQLite + Alembic（PostgreSQL へ段階移行可能な設計、head 追従） | `backend/alembic/versions/` |
| 非同期 | Celery + Redis | 学習・決着バッチ・トレンド同期・通知監視・ドリフト検知。beat 一元化（手動 `.delay()` 禁止） |
| リアルタイム | FastAPI WebSocket / SSE | 推論トレース配信・通知 push |
| ML | xgboost / RandomForest / LSTM / Transformer（移植）+ **モデルレジストリ層（新設）** | torch は CPU。実験管理（MLflow 等）は P5 で要否判断 |
| 通知 | Web Push（VAPID, `pywebpush`）を第一候補 + アダプタ差し替え可能 | アプリ内トースト + OS 通知。PWA 化は今回対象外 |
| チャート | `lightweight-charts`（TradingView OSS）等の軽量ライブラリ | ローソク足・出来高・複数時間軸 |

Redis は Market Lens（`market-lens-redis` / 6379）と同居しうるため、**Alpha Forge 専用の DB 番号 or キープレフィックス**で名前空間を分離する。

## 4. 新規領域の位置づけ

| 領域 | 配置 | 依存（移植元） |
|:--|:--|:--|
| N1 モデルレジストリ + champion/challenger + shadow + 昇格ゲート | `services/registry/` | `ml_predictor` / `ensemble_predictor` / `pool_*` / `eval_metrics` / `backtester` |
| N2 統合 Prediction Ledger | `services/ledger/` | `pick_outcome_service` / `pick_simulation_service` / `prediction_accuracy_service` / `performance_ledger_service` |
| N3 確度の事後較正（isotonic / Platt） | `services/registry/calibration.py` | `eval_metrics`（Calibration curve / Brier） |
| N4 AI 思考の可視化 | `services/inference/` + `routers/inference.py`（WS/SSE）+ frontend `components/pipeline/` | 既存サービスを stage として束ねる |
| N5 ドリフト検知（PSI）+ 再学習トリガ | `services/registry/drift.py` + `tasks.py` beat | `feature_engineering` / `panel_feature_service` |
| N6 Web Push（VAPID） | `services/notify/webpush.py` + `routers/notify.py` | `notification_service`（アダプタ追加） |

## 5. データフロー（1 営業日）

1. **寄り付き前（JST 08:50 目安）**: beat → 候補プール生成（`ranking` / `signal_scan`）→ 推論オーケストレータが中長期・短期それぞれ実行 → 各ステージのトレースを `inference_traces` へ、最終ピックを **Prediction Ledger** へ（`feature_snapshot` 完全版 + `source_contributions`）。challenger は **shadow 推論**で並走し `shadow_predictions` へ。
2. **場中（9:00–15:30 JST）**: 保有監視 → 売買タイミング判定 → トリガ時に Web Push + アプリ内通知（承認キューへ）。
3. **大引け後（15:00 以降）**: 当日確定 OHLC で到達判定の材料を更新。EOD レビュー → learned heuristics を翌日プロンプトへ。
4. **夜間（日次）**: 決着記録バッチ（horizon 到来分の 3 / 20 / 60 営業日）→ 評価指標更新（較正・IC・成績）→ 軽量再学習 → PSI ドリフト評価 → 必要なら追加再学習。
5. **週次**: フル再学習 → challenger 再構築 → 昇格ゲート判定（提案のみ、`model_promotions` にログ）→「今週何を学習したか」差分サマリ生成。

## 6. リアルタイム配信

- **SSE**（`GET /api/inference/{run_id}/stream`）: 推論トレースのステージ更新をライブ配信。フロントは DAG ビューと Thinking パネルを更新。
- **WebSocket**（`/ws/notifications`）: 承認キュー・通知センターの push。
- LLM トークンストリーミングは推論オーケストレータ内で `anthropic_client` のストリームを受け、ステージ ③ のイベントとして SSE に中継。
- リプレイは `inference_traces` を時系列に読み出して同じイベント列を再生する専用エンドポイント。

## 7. セキュリティ境界

- 外部由来テキスト（Vault 本文・ニュース本文・四季報本文）は **LLM プロンプトへ注入しない**。注入するのは frontmatter / 構造化フィールドのみ。境界は `services/vault/` と `services/picks/*_prompt` に集約し、テストで固定。
- 継続学習の教師信号は**自分の実測値のみ**（外部テキストを学習根拠にしない）。
- シークレット（`ANTHROPIC_API_KEY` / `JQUANTS_API_KEY` / VAPID 秘密鍵 / `ML_SECRET_KEY`）は env。起動時に必須チェック。
- CSP は nonce ベース。セキュリティヘッダ（HSTS / X-Content-Type-Options / X-Frame-Options DENY / Referrer-Policy / Permissions-Policy）。
- Vault は読み取り専用が原則。書き込みは専用マーカー区画に限定し、実行前にユーザー確認。

## 8. 可観測性

- 構造化ログ（`request_context` 移植）。
- `inference_traces`（全推論のリプレイ可能トレース）。
- API コスト台帳（`api_cost` 移植、LLM トークン・費用）。
- ヘルスチェック（`/health`：DB / Redis / 外部 API 到達性）。
- モデルレジストリの昇格判定ログ（`model_promotions`）。

## 9. Market Lens との分離

| 項目 | Market Lens | Alpha Forge |
|:--|:--|:--|
| リポジトリ | `market-lens` | `claude-code-market-lens`（別） |
| backend ポート | 8001 | 8002 |
| frontend ポート | 3000 | 3001 |
| Redis 名前空間 | 既定 | 専用 DB 番号 or キープレフィックス |
| Vault 書き込み | `market-note:{phase}` マーカー | Alpha Forge 専用マーカー（衝突回避）、原則 read-only |
| venv | `market-lens/.venv` | Alpha Forge 専用 venv |
| celerybeat スケジュール DB | `market-lens/celerybeat-schedule` | Alpha Forge リポジトリ内の別ファイル |
