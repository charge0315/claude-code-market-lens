# PRD — Alpha Forge（AI 銘柄ピック & 継続学習トレーディング端末）

> コードネーム: **Alpha Forge** / リポジトリ: `claude-code-market-lens`（Market Lens とは完全別リポジトリ）
> 出典: `新規プロジェクト構築プロンプト.md` / 本 PRD はそれを実装可能な粒度に落としたもの

---

## 1. 背景と目的

複数の独立した情報源（4分析・最新トレンド・毎日のニュース・四季報・Obsidian ナレッジ）を統合し、
**中長期銘柄**と**短期（デイトレ）銘柄**をそれぞれ「推奨買値 / 損切ライン / 推奨売値」の 3 値付きで
ピックアップする AI トレーディング支援端末を構築する。

差別化の核（＝最優先で設計する 2 点）:

1. **継続学習ループ**: すべての予測を台帳化し、決着結果からモデルを再学習。予測精度の成長を指標化・可視化。
2. **AI 思考のリアルタイム可視化**: スコア計算 → LLM 推論 → 最終合成までのパイプラインを端末上でライブ表示。

保有ポートフォリオに対しては AI が売り時・買い増し時を判定し、リアルタイム通知する。
UI/UX はプロ向けトレーディング端末（Bloomberg Terminal / MARKETSPEED II / TradingView）に寄せる。

## 2. スコープ

### In Scope
- 日本株（東証上場、銘柄コード 4 桁）のみ。
- 銘柄ピック 2 系統: **中長期**（数週間〜数ヶ月）/ **短期**（当日〜3 営業日、デイトレ的運用）。
- 各ピックに **根拠（rationale）** と **確度（0–100、事後較正済み）** を必須表示。
- 継続的モデル学習パイプラインと精度成長の可視化。
- 保有ポートフォリオの売買タイミング判定 + リアルタイム通知（Web Push + アプリ内）。
- プロ端末風 UI/UX。

### Out of Scope（明示的に作らない）
- **ブローカーへの実発注は一切行わない。** 提案と通知のみ。約定は人間が手動。
- 米国株・暗号資産・FX・先物。
- 投資助言業に該当する個別断定的な投資勧誘。出力は「分析結果・参考情報」として提示し、免責を UI 常設。
- 資金移動・入出金・自動売買・自動ポジション管理。

## 4. ユーザーストーリー（受け入れ基準に対応）

- US-1: 中長期・短期それぞれのピックが、根拠 + 確度 + 3値付きで毎営業日生成される。
- US-2: サーバ側で `損切 < 現在値 < 売値` かつ `損切 < 買値 < 売値` が強制される（不整合は却下 or 目安補完）。
- US-3: すべての予測が台帳化され、決着後（短期 3 / 中長期 20・60 営業日）に評価指標が自動更新される。
- US-4: 再学習が定期（夜間日次 + 週次フル）+ ドリフト（PSI / 直近精度劣化）で発火し、challenger が shadow で並走。昇格は**提案のみ**（自動昇格既定 OFF）。
- US-5: 確度が isotonic / Platt で事後較正され、UI で「同確度バケットの過去実測勝率」が確認できる。
- US-6: モデルラボで精度の成長曲線（AUC / IC / 較正誤差 / 勝率）とピック累積成績（エクイティカーブ）が見える。
- US-7: 銘柄詳細で AI の思考パイプライン（データ収集 → サブスコア → LLM → 合成 → 3値 → 検証）がライブに流れ、後からリプレイできる。
- US-8: 保有銘柄の売買タイミングでリアルタイム通知が届き、承認制で約定結果を API で戻せる。
- US-9: アプリはブローカー発注を一切行わない。
- US-10: 騰落色 赤 = 上げ / 緑 = 下げ。時刻は JST。銘柄コード 4 桁。
- US-11: 外部由来テキストは frontmatter のみ注入。継続学習の根拠は自分の実測値のみ。

## 5. 機能要件

### 5.1 継続学習ループ（最優先）

| ID | 要件 |
|:--|:--|
| CL-1 | **予測台帳**: 全ピック・売買判定を、予測時点で確定していた情報だけで永続化（`pick_id` / `issued_at`(JST) / `horizon_type` / `symbol` / `direction` / `entry`,`stop`,`target` / `sub_scores`(tech/trend/fund/sent) / `composite_score`,`concordance`,`confidence` / `feature_snapshot`（全特徴量スナップショット）/ `rationale`（構造化+自然文）/ `model_version` / `source_contributions`） |
| CL-2 | **決着記録**: horizon 経過後（短期 当日〜3 / 中長期 5・20・60 営業日）にバッチで、実現リターン・勝敗・stop/target 到達有無と順序・MFE/MAE・TOPIX 超過リターンを確信度バケット / 方向コホート付きで格納 |
| CL-3 | **評価指標（時系列保持）**: 確度較正（バケット別実測勝率・Calibration curve・Brier）/ ランキング有効性（IC・precision@k）/ ピックポートフォリオ成績（エクイティカーブ・勝率・平均 R 倍数・期待値・最大 DD・Sharpe）/ 情報源別 ablation（四半期） |
| CL-4 | **再学習トリガ**: 定期（夜間日次の軽量更新 + 週次フル、celery-beat）/ ドリフト検知（特徴量分布 PSI・直近 N 件の精度劣化）で追加再学習 |
| CL-5 | **ウォークフォワード検証必須**。時系列 CV のみ。未来情報リークを構造的に排除 |
| CL-6 | **モデルレジストリ & 昇格ゲート**: champion / challenger 方式。challenger は shadow 推論で本番と並走。昇格条件（すべて満たす）= ホールドアウトで champion 超過 かつ 較正悪化なし かつ 直近 20 営業日のペーパー成績が非劣化。昇格・却下は**提案のみ**（自動昇格既定 OFF、env でゲート）。判定ログを残す |
| CL-7 | **確度較正**: isotonic / Platt scaling で事後較正してから UI へ出す |
| CL-8 | **成長の可視化**: モデルバージョン別評価指標時系列（折れ線）/ ピック累積成績エクイティカーブ（中長期・短期・合算）/「今週何を学習したか」差分サマリ（特徴量重要度の変化、追加決着データ件数） |

### 5.2 AI 思考のリアルタイム可視化

| ID | 要件 |
|:--|:--|
| VZ-1 | 推論をステージ化: ①データ収集 ②サブスコア計算 ③定性オーバーレイ（LLM）④合成 ⑤3値ブラケット決定 ⑥サーバ側検証 |
| VZ-2 | 各ステージの進行・中間結果を SSE / WebSocket でフロントへストリーム |
| VZ-3 | サブスコアは特徴量レベルの寄与（SHAP 相当）を bar 表示 |
| VZ-4 | LLM 推論はトークンストリーミング表示（Thinking パネル） |
| VZ-5 | パイプラインを DAG ビュー表示（ノード = ステージ、状態 = pending / running / done / failed） |
| VZ-6 | 全トレースを `inference_traces` に永続化し、後からリプレイ可能 |

### 5.3 スコアリング & 確度

| ID | 要件 |
|:--|:--|
| SC-1 | technical / trend / fundamental / sentiment の各スコア（0–100）→ `composite_score` |
| SC-2 | `concordance` = 4分析の方向一致度、`direction` = bullish / bearish / neutral |
| SC-3 | 確度は較正済み確率ベースの 0–100。UI では確度バケット（高/中/低）と較正の裏付け（過去の同バケット実測勝率）を併記 |
| SC-4 | AI が売買銘柄を提案する全機能で 3値（推奨買値 / 損切値 / 推奨売値）を必須明記（model / API / UI / 通知すべて）。サーバ側で整合検証 |
| SC-5 | ハード除外ルール（Market Lens E1〜E3 相当）: SELL 判定候補をロングに混ぜない、実測勝率ゲート等 |

### 5.4 ポートフォリオ売買タイミング判定 & 通知

| ID | 要件 |
|:--|:--|
| PF-1 | ユーザーが保有銘柄（数量・取得単価・取得日）を登録 |
| PF-2 | 監視は平日 9:00–15:30 JST（祝日非対応、大引け 15:00） |
| PF-3 | AI が保有ごとに「継続保有 / 一部利確 / 損切 / 買い増し」を判定し、根拠と 3値（更新後 stop/target、買い増し時 entry）を提示 |
| PF-4 | トリガ発生時にリアルタイム通知（Web Push（VAPID）+ アプリ内）。銘柄・アクション・根拠サマリ・3値・確度を含む |
| PF-5 | **承認制**: AI は提案チケットのみ。約定・記録は人間、結果を API で戻す（HITL） |
| PF-6 | 大引け後に EOD レビュー（当日の判定と結果 → 翌日プロンプトへ learned heuristics 注入） |

## 6. 非機能要件

- **言語・スタイル**: コミット / docs / コメントは日本語。コメントは Why。Python 全シグネチャ型付き・`async/await`・Pydantic v2 `frozen=True`・`Any` 禁止。TS `any` 禁止・絶対 import（`@/...`）・関数コンポーネント + Hooks。CSS は Vanilla のみ（Tailwind 禁止）。
- **テスト**: 最低カバレッジ 80%。unit / integration / E2E。TDD（RED→GREEN→REFACTOR）。DB 書き込みテストは per-file 隔離 fixture。
- **セキュリティ**: シークレットは env / secret manager。入力検証は境界。CSP（nonce ベース）・セキュリティヘッダ。**LLM プロンプトへの外部テキスト注入禁止**（frontmatter のみ）。
- **可観測性**: 構造化ログ、推論トレース永続化、API コスト計測（LLM トークン・費用の台帳化）、ヘルスチェック。
- **予算上限は安全装置であって目標ではない。自己保存を動機にしない。config / コードの自動適用はしない。**
- **性能**: ダッシュボード初期表示の主要指標 2.5s 以内目安。リアルタイム更新はイベント駆動。
- **検証環境**: Windows / PowerShell（コマンド連結は `;`、`&&` 不可）。
- **CI**（push 前にローカル全通し）: backend `ruff` / `black --check` / `mypy` / `bandit` / `pytest -q`（+ cov）/ OpenAPI エクスポート。frontend `tsc --noEmit` / `TZ=UTC jest` / `eslint .` / `next build`。E2E Playwright。
- Git: `git add -A` 禁止（対象ファイル明示 add）。フェーズ完了ごとにコミット & プッシュ。

## 9. リスクと対策

| リスク | 対策 |
|:--|:--|
| プロンプトインジェクション（Vault 本文経由） | 全ソースで frontmatter / 構造化フィールドのみ注入。本文は読まない。継続学習の根拠は実測値のみ |
