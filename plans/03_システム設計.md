## 1. データモデル（新 baseline）

Market Lens の `0001_baseline_schema` を土台に、Alpha Forge 用に再構成する。以下は **新規 / 拡張テーブル**を中心に記載（移植テーブル: `stocks` 系マスタ、`model_registry`、`predictions`、`portfolios`、`notifications`、`api_costs`、`stock_pick_runs` 等はほぼそのまま）。

### 1.1 予測台帳（CL-1）

**`prediction_ledger`** — すべてのピック・売買判定を予測時点確定情報のみで永続化。

| 列 | 型 | 説明 |
|:--|:--|:--|

| `issued_at` | TEXT | ISO8601 JST |

| `symbol` | TEXT | 4 桁コード |
| `direction` | TEXT | `bullish` / `bearish` / `neutral` |

| `composite_score` | REAL | 合成 |
| `concordance` | REAL | 方向一致度 0–1 |
| `confidence_raw` | REAL | 較正前 0–100 |

### 1.2 決着記録（CL-2）

| 列 | 型 | 説明 |
|:--|:--|:--|
| `outcome_id` | TEXT PK | |
| `pick_id` | TEXT FK | `prediction_ledger` |
| `horizon_days` | INTEGER | 短期: 1/2/3、中長期: 5/20/60 |
| `resolved_at` | TEXT | |
| `realized_return` | REAL | エントリー→exit |

### 1.3 評価指標（CL-3）

**`eval_snapshots`** — 時系列で保持し成長曲線にする。

| 列 | 説明 |
|:--|:--|
| `snapshot_id` PK / `computed_at` / `scope`（`mid_term`/`short_term`/`combined`）/ `model_version` |
| `metric_name`（`brier` / `ic` / `precision_at_k` / `win_rate` / `avg_r_multiple` / `expectancy` / `max_dd` / `sharpe` / `calib_error` / `auc`）|
| `metric_value` / `sample_n` / `horizon_days` / `confidence_bucket`（該当時）|

**`calibration_curves`** — バケット別（予測確度 → 実測勝率）の点列を JSON で保持。
**`source_ablations`** — 四半期ごと、各ソース除外時の指標差分。

### 1.4 モデルレジストリ & 昇格（CL-6, N1）

**`model_registry`**（移植・拡張）: `version` / `model_type` / `ticker` or `__pool__` / `objective` / `trained_at` / `artifact_path` / `val_metrics`(JSON) / `feature_list`(JSON)。

**`model_champions`** — 系統ごとの現行 champion。

| 列 | 説明 |
|:--|:--|
| `lane` PK（`mid_term_pool` / `short_term_pool` / `per_ticker_xgb` …）/ `champion_version` / `promoted_at` / `promoted_by`（`manual` のみ、既定）|

**`model_promotions`** — 昇格ゲートの判定ログ（提案のみ）。

| 列 | 説明 |
|:--|:--|
| `promotion_id` PK / `lane` / `challenger_version` / `champion_version` / `evaluated_at` |
| `holdout_delta`（challenger − champion、正で改善）/ `calib_regressed`（bool）/ `paper_perf_delta` / `paper_days`（≥20 必須）|
| `verdict`（`propose_promote` / `hold` / `reject`）/ `applied`（既定 0、env `MODEL_AUTO_PROMOTE=false`）/ `rationale`(JSON) |

**`shadow_predictions`** — challenger の shadow 推論結果（`prediction_ledger.is_shadow=1` と対で、challenger 版の詳細）。

### 1.5 ドリフト検知（CL-4, N5）

**`drift_snapshots`**: `computed_at` / `feature_name` / `psi` / `baseline_window` / `current_window` / `drift_flag`（PSI > 0.2 目安）/ `triggered_retrain`（bool）。

### 1.6 AI 思考トレース（VZ-6, N4）

**`inference_traces`** — リプレイ可能な全トレース。

| 列 | 説明 |
|:--|:--|
| `trace_id` PK / `run_id` / `pick_id`（確定後に紐付け）/ `symbol` / `horizon_type` / `started_at` / `finished_at` / `status` |
| `stage`（`collect` / `subscore` / `llm_overlay` / `synthesis` / `bracket` / `verify`）|
| `stage_status`（`pending` / `running` / `done` / `failed`）/ `stage_seq` |
| `payload`(JSON)（中間結果: フェッチ成否、サブスコアと SHAP 寄与、LLM トークン列、合成内訳、RR 比、検証結果）|
| `event_at` | イベント時刻（SSE 再生用） |

### 1.7 ポートフォリオ & 通知（PF-*, N6）

- **`portfolios`**（移植）: `symbol` / `quantity` / `avg_cost` / `acquired_at`。
- **`portfolio_signals`**: `symbol` / `evaluated_at` / `action`（`hold` / `trim` / `stop_loss` / `add`）/ `entry`/`stop`/`target`（更新後）/ `confidence` / `rationale` / `status`（`proposed` / `approved` / `rejected` / `executed`）。
- **`push_subscriptions`**: `endpoint` PK / `p256dh` / `auth` / `created_at` / `user_agent` / `revoked`。
- **`notifications`**（移植）: `run_date` / `ticker` / `kind` 一意制約で重複防止。`channel`（`in_app` / `web_push`）を追加。
- **`eod_reviews`**: `review_date` / `summary` / `learned_heuristics`(JSON)。

## 3. 主要アルゴリズム設計

### 3.1 推論オーケストレータ（stage DAG, N4）

```
run(symbol, horizon_type) -> Pick | Rejected
  stage collect     : data/ + vault/ から特徴量素材を集める。各ソースの成否を trace へ
  stage subscore    : scoring/ で technical/trend/fundamental/sentiment を 0–100。SHAP 寄与を trace へ
  stage llm_overlay : anthropic_client の forced tool-use。トークンを stream して trace へ
  stage synthesis   : recommender で composite_score/concordance/direction。source_contributions を算出
  stage bracket     : ATR・支持抵抗・RR 比から entry/stop/target。confidence_raw を算出
  stage verify      : stop<price<target かつ stop<entry<target。E1〜E3 ハード除外。calibration 適用 -> confidence
  -> prediction_ledger へ書き込み（is_shadow=0）。challenger があれば shadow で再実行し shadow_predictions へ
```

- 各 stage は「既存の移植サービスを呼ぶだけの薄いラッパ」。stage 間は `frozen` な中間 DTO を渡す。
- stage 失敗は trace に `failed` を記録し、以降を skip（ピックは `rejected` 扱い、理由付き）。
- トレースは逐次 `inference_traces` へ INSERT（リプレイ用）。SSE はこの INSERT をトリガに配信。

### 3.2 確度の事後較正（CL-7, N3）

- 教師データ: `pick_outcomes`（決着済み、horizon 別）。`confidence_raw` → 実現勝敗。
- 手法: サンプル数に応じて **isotonic**（十分なとき）/ **Platt**（少数のとき）を選択。horizon_type × direction ごとに較正器を学習し `data/calibrators/` に保存。
- 台帳が薄い初期（決着 n 小）は恒等写像へフォールバック（`confidence = confidence_raw`）し、`calibration_curves` に「未較正」フラグ。
- UI へ出すのは較正後 `confidence` と、同 `confidence_bucket` の過去実測勝率（`pick_outcomes` 集計）。

### 3.3 昇格ゲート（CL-6, N1）

```
evaluate(lane, challenger_version):
  champion = model_champions[lane].champion_version
  holdout_delta   = metric(challenger, holdout) - metric(champion, holdout)   # walk-forward, 時系列 CV のみ
  calib_regressed = calib_error(challenger) > calib_error(champion) + ε
  paper_perf_delta, paper_days = paper_perf(challenger) - paper_perf(champion) # shadow の擬似執行
  if paper_days < 20: verdict = hold  # 最小ペーパー成績日数（確定事項）
  elif holdout_delta > 0 and not calib_regressed and paper_perf_delta >= 0: verdict = propose_promote
  else: verdict = reject if holdout_delta < 0 else hold
  記録 model_promotions（applied=0）。MODEL_AUTO_PROMOTE=false（既定）では API 承認でのみ champion 差し替え
```

### 3.4 ドリフト検知（CL-4, N5）

- 特徴量ごとに baseline window（学習期間）と current window（直近 N 営業日）の分布を 10 分位 bin 化し **PSI** を計算。
- `PSI > 0.2` の特徴量が閾値本数を超える or 直近 N 件の予測精度（`eval_snapshots` の rolling）が既定比で劣化 → `triggered_retrain=1` で追加再学習タスクを enqueue。
- ドリフト結果は `drift_snapshots` へ。UI（モデルラボ）に PSI 推移を表示。

### 3.5 決着記録バッチ（CL-2）

- Market Lens `pick_outcome_service` の「後追い解決」パターンを踏襲: `run_date` を古い順に 1 つ選び、保有期間 + 約定窓 + バッファ経過分のみ解決。
- 拡張: 1 ピックにつき `horizon_days ∈ {1,2,3}`（短期）/ `{5,20,60}`（中長期）で複数行。yfinance 日次 OHLC で指値約定 → トリプルバリア。MFE/MAE と `first_hit`、TOPIX 超過を算出。

### 3.6 再学習スケジュール（celery-beat）

| タスク | 時刻（JST）目安 | 内容 |
|:--|:--|:--|
| ピック生成（中長期・短期） | 08:50 | 推論オーケストレータ → Ledger。shadow 並走 |
| 保有監視 | 09:00–15:30 の周期 | 売買タイミング判定 → 通知 |
| 決着解決 | 夜間 | horizon 到来分を解決 |
| 評価指標更新 | 決着後 | `eval_snapshots` / `calibration_curves` |
| 軽量再学習 | 夜間日次 | per-ticker ローテーション（Market Lens 踏襲） |
| PSI ドリフト評価 | 夜間日次 | `drift_snapshots`、必要なら追加再学習 |
| フル再学習 + challenger 構築 + 昇格ゲート | 週次 | `model_promotions` へ提案 |
| EOD レビュー | 16:31 前後 | learned heuristics |
| 週次学習差分サマリ | 週次 | `/api/eval/weekly-learning` の材料 |

手動での `.delay()` 投入はしない（Market Lens と同じく quota 無駄打ち防止）。

## 4. フロントエンド設計

### 4.1 画面（5 つ）

1. **ダッシュボード** — 中長期 / 短期タブ、確度順、3 値、根拠プレビュー、当日データソース取得状況。
2. **銘柄詳細** — `lightweight-charts`（複数時間軸）+ 4 分析内訳 + **AI 思考トレース（ライブ / リプレイ）**（DAG ビュー + Thinking パネル + サブスコア SHAP bar）。
3. **ポートフォリオ** — 保有一覧、AI 判定、通知履歴、承認キュー（approve / reject / report-fill）。
4. **モデルラボ** — 成長曲線、Calibration curve、モデルバージョン比較、再学習ログ、PSI ドリフト、週次学習差分。
5. **通知センター** — Web Push 購読管理、通知履歴。

全画面フッタに免責を常設。

### 4.2 UI 規約（プロ端末デファクト）

- near-black `#0a0e14` 系 + プライマリブルー `#1f6feb` 系。高密度・低余白。
- **騰落色: 上昇・利益 = 赤（`--color-gain`）/ 下落・損失 = 緑（`--color-loss`）/ `--color-flat`**。海外仕様で書かない。
- 数値は `font-variant-numeric: tabular-nums`・右寄せ・カンマ区切り・小数点位置統一。
- テーブルは共通 `DataTable`（生 `<table>` 禁止、`caption` 必須）。
- `@media` max-width は **640 / 768 / 900 / 1280 のみ**。アニメは `transform` / `opacity` のみ。
- マルチペイン / ドッキング可能レイアウト、ウォッチリスト、ホットキー。

### 4.3 リアルタイム

- `lib/realtime/` に SSE クライアント（推論トレース）と WS クライアント（通知）。
- 再接続・バックオフ・イベント再生（リプレイ時は `/replay` を SSE と同じレンダラに流す）。

## 5. テスト戦略

- backend: unit（`eval_metrics` / `labeling` / `ts_validation` / 較正器 / 昇格ゲート / PSI は I/O なし純関数で厚く）、integration（各ソースの取得・欠損フォールバック、Ledger→決着→指標の一連、承認フロー）、E2E（ピック生成、3 値整合、ライブトレース表示、通知配信、承認）。
- DB 書き込みを増やすテストは per-file の隔離 fixture。
- frontend: jest（`TZ=UTC`）+ Playwright。視覚回帰は 320/768/1024/1440。a11y・reduced-motion・コントラスト。
- カバレッジ 80% 以上（CI でゲート）。
